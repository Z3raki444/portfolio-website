01 / THE PROBLEM

What needed solving?

An API returns useful measurements, but an analytics database needs consistent types, valid values and safe re-runs. This pipeline turns a live weather response into structured observations without inserting duplicate city/timestamp records.

03 / IMPLEMENTATION

What I built.

01

Collect observations

Request temperature, humidity, precipitation, wind speed, weather code and observation timestamps for Berlin, Hamburg, Munich, Frankfurt and Cologne.

02

Validate and transform

Convert timestamps and numeric values, reject missing required fields, check humidity and non-negative measurements, and filter duplicate city/timestamp observations.

03

Load safely and schedule

Load into PostgreSQL with an ON CONFLICT upsert keyed by city and observation time. Run the extract → transform → load DAG hourly with Airflow.

04 / ENGINEERING TRADE-OFFS

Scope and limitations.

An idempotent load is useful when a scheduled job retries. The repository describes a local Docker-based demonstration; offline CI checks transformations and does not verify a fully deployed production environment.

05 / WHAT'S NEXT

Where I'd take it.
